# iso-prerender

![English](https://img.shields.io/badge/lang-English-4a5568) [![简体中文](https://img.shields.io/badge/lang-简体中文-e8b45c)](README.zh-CN.md)

A pre-rendering pipeline for 2:1 isometric games, and a farming scene built with it.

The scene is a rendering slice rather than a finished game: there is no gameplay loop and
no progression. It exists to exercise the pipeline end to end, and the pipeline is the part
meant to be reused.

No Blender, no modelling files, no third-party runtime libraries. Every sprite, material,
pattern, glyph and shader in this repository is generated by the code in this repository.

What the pipeline does: the atlases carry a normal and a material channel alongside the
colour, and per-pixel depth is derived from the projection rather than baked, so occlusion
is a hardware depth test instead of a sort order.

## Run it

```bash
git clone https://github.com/he1ta0/iso-prerender.git
cd iso-prerender
npm run build     # ~7 s, no dependencies
npm run serve     # http://127.0.0.1:8123
```

`npm run single` instead writes `dist/homestead98.html` — one 2.99 MB file with every
module and both atlases inlined, no server required.

Running the game needs a WebGL2 browser. `build`, `serve`, `single` and `sheet` use only
Node built-ins, so `npm run build` works on a fresh clone with no `npm install` at all.
Puppeteer and gifenc are devDependencies for the screenshot, verification and timelapse
tools, and nothing else.

## The pipeline

Bake offline, light at runtime.

```
tools/models/*.mjs      model descriptions as plain code — the only "art source"
        │               mesh, UVs, per-vertex AO, material patterns
        ▼
tools/lib/render.mjs    offline rasteriser, no GPU
        │
        ▼
assets/                 4 images sharing ONE packing layout
        │               albedo │ normal │ material │ stamp   (2048×512, shelf-packed)
        ▼
src/gl/renderer.js      one UV set addresses all four
                        G-buffer → light pass → composite
        ▼
the frame
```

The thesis in one line: **make the light lower-frequency than the pixel.** Sprites are baked
as hard pixels — nearest-neighbour, integer-aligned, banded — while the lighting is a
continuous field multiplied over the top at runtime. So the silhouette stays crisp and the
light still breathes: the sun crosses the sky, shadows rotate, a lantern lights the wall it
hangs on, and sunlight comes through the windows and moves across the floor as the day
passes.

## Implementation notes

### 1. Depth is already in the pixels — there is no baked depth map

Painter's-algorithm sorting is a partial order crammed into a total order, so two sprites
that overlap on screen and interleave in depth have no correct draw order at all. The usual
fix is to bake a depth channel alongside the art.

Not needed here. `normal.a` already stores the world height of the surface each texel draws,
and the projection is orthographic and invertible, so depth is a closed form:

```glsl
// src/gl/shaders.js:158
float xpy = (rel.y + worldZ * u_iso.z) / u_iso.y;   // this is x + y
float dep = xpy + u_depthK * worldZ + v_bias;
gl_FragDepth = clamp((dep + u_depthOrigin) / u_depthRange, 0.0, 1.0);
```

`x + y` falls straight out of the projection, so it never has to solve for `x` and `y`. Two
lines buy a real 24-bit depth buffer over all geometry, for zero extra bytes of asset.

### 2. Window light is a 3D-DDA, not a fixed-step march

A fixed step through a shadow volume either leaks light through walls or crawls. This walks a
voxel transmittance volume with a 3D-DDA instead, which cannot step over a caster.

Each window is a hole in a sealed box, and the shape of the hole is what decides where the
light lands and how far it throws (`throw = opening height / tan(sun elevation)`). Stained
glass gets its colour from per-voxel transmission, so five colours need no new shader. → §5

### 3. Failures fall in the safe direction, and say so

An earlier version ghosted interior walls using a per-pixel focus map. It worked — until the
map failed to generate, at which point every cut-away wall silently turned solid and swallowed
the furniture behind it, with nothing in the console.

Now the interior does not depend on the map at all, the shader has a fallback branch, and the
renderer counts frames without focus and warns you by name that you are probably running a
stale module. → §1

## What is reusable

This is not a library, but most of it is not game-specific either.

| | file | coupling |
|---|---|---|
| PNG encoder **and** decoder (indexed + RGBA) | `tools/lib/png.mjs` | standalone, ~150 lines, zero deps |
| Shelf packer | `tools/lib/pack.mjs` | standalone, 93 lines |
| Offline rasteriser, AO bake, material patterns | `tools/lib/render.mjs` | wants a mesh format; the AO bake is generic |
| Depth from the projection | `SPRITE_FS` in `src/gl/shaders.js` | needs orthographic iso; ~5 lines |
| Voxel transmittance + DDA interior light | `src/interior.js` and `LIGHT_FS` | the march is generic, the volume build is game-shaped |
| Bitmap font → per-colour glyph atlases | `src/font.js` | standalone |
| Single-file bundler | `tools/build-single.mjs` | standalone |
| Headless screenshot / timelapse / verify harness | `tools/*.mjs` | puppeteer via `tools/lib/browser.mjs` |

## Repository layout

```
src/            13 runtime modules — the scene and its lighting runtime.
tools/models/   The models, as code. Buildings, chapel, furniture, crops, characters.
tools/lib/      Offline renderer, shelf packer, PNG codec, shared tool helpers.
tools/          Build, bundle, verify, screenshot, probe, timelapse and sheet entry points.
assets/         Build output: 2 sets × (albedo, normal, material, stamp) + manifests.
docs/img/       The images in this README.
```

```bash
npm run build      # pre-render both AOV atlases            -> assets/
npm run verify     # 22 end-to-end assertions against a live frame
npm run shot       # headless screenshots, 12 times of day and weathers
npm run timelapse  # the GIFs above
npm run sheet      # the labelled atlas sheets above
npm run single     # one self-contained HTML file
```

`npm run verify` is the honest one. It boots the game, renders, and then measures: that the
room is lit, that the sun moves the shading, that sunlight reaches the interior, that a
villager behind a building is revealed **and that only the 1.6% of the facade actually in
front of them fades**, that ghosted walls still block the sun. It fails loudly rather than
producing a plausible screenshot of a broken build.

The build is reproducible: the atlas PNGs come out byte-identical across runs, so you can
diff your output against mine. `npm run build -- --stamp` puts a build time in the manifest if
you want one.

## AI involvement

Built with an AI coding assistant (DeepSeek Harness) under my direction. The architecture, the
debugging and the technical calls are mine; the assistant wrote much of the code and most of
the prose, including in `docs/DEEP-DIVE.md`.

Said up front rather than left to be discovered, because the real question is not who typed it
but whether the claims hold — and those are checkable. `npm run verify` prints what it
measured, and the build is reproducible so you can diff it. The deep-dive is specific enough
to be wrong: it documents the silent failure above, a table lamp modelled at the wrong height
that only broke once the depth buffer took over, and replacing a guessed step size with a
proof that the step cannot skip a caster.

No external art is used and none is hand-drawn. Every sprite comes out of `npm run build`
applied to `tools/models/`; there is no asset file here that the repository cannot regenerate.
